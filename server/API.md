
# Документация REST API интернет-магазина TechMarket

## 1. Общие сведения

REST API интернет-магазина TechMarket разработано на Node.js с использованием Express.

API обеспечивает взаимодействие клиентской части приложения на React с сервером и базой данных PostgreSQL.

**Базовый адрес API:** `http://localhost:3001`

Обмен данными осуществляется по протоколу HTTP в формате JSON.

Основные HTTP-методы:
- `GET` — получение информации.
- `POST` — отправка и создание данных.

## 2. Список API-маршрутов

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/test` | Проверка работы сервера |
| GET | `/api/db-test` | Проверка подключения PostgreSQL |
| GET | `/api/products` | Получение списка товаров |
| GET | `/api/products/:id` | Получение товара по идентификатору |
| POST | `/api/orders` | Оформление заказа |
| GET | `/api/orders/count` | Получение количества заказов |
| POST | `/api/support` | Отправка обращения в поддержку |
| GET | `/api/support/count` | Получение количества обращений |

## 3. Описание API-маршрутов

### 3.1. Проверка работы сервера

**Метод:** GET

**Маршрут:** `/api/test`

**Описание:** проверяет доступность серверной части приложения.

**Пример ответа (200 OK):**

```json
{
  "message": "Привет от сервера TechMarket!",
  "success": true
}
```

### 3.2. Проверка подключения к PostgreSQL

**Метод:** GET

**Маршрут:** `/api/db-test`

**Описание:** проверяет соединение сервера с базой данных PostgreSQL.

**Пример ответа (200 OK):**

```json
{
  "success": true,
  "message": "PostgreSQL подключён!",
  "database": "techmarket_db",
  "server_time": "2026-11-02T10:00:00.000Z"
}
```

Значение `server_time` определяется PostgreSQL при выполнении запроса.

### 3.3. Получение списка товаров

**Метод:** GET

**Маршрут:** `/api/products`

**Описание:** возвращает список всех товаров из таблицы `products`.

**Пример ответа (200 OK):**

```json
[
  {
    "id": 1,
    "name": "Смарт ТВ приставка",
    "category": "ТВ приставки",
    "price": 4990,
    "description": "Описание товара",
    "image": "product1.jpeg",
    "fullDescription": "Подробное описание товара",
    "specifications": {}
  }
]
```

Фактические значения полей определяются записями в базе данных. Поле `specifications` содержит характеристики товара.

### 3.4. Получение товара по идентификатору

**Метод:** GET

**Маршрут:** `/api/products/:id`

**Описание:** возвращает информацию об одном товаре.

**Параметр:** `id` — положительное целое число, идентификатор товара.

**Пример запроса:**

```http
GET /api/products/1
```

**Успешный ответ (200 OK):** JSON-объект товара с полями `id`, `name`, `category`, `price`, `description`, `image`, `fullDescription`, `specifications`.

**Возможные ошибки:**

- `400 Bad Request` — некорректный идентификатор.
- `404 Not Found` — товар не найден.

Пример ответа при отсутствии товара:

```json
{
  "message": "Товар не найден"
}
```

### 3.5. Оформление заказа

**Метод:** POST

**Маршрут:** `/api/orders`

**Описание:** принимает данные покупателя и выбранных товаров, рассчитывает стоимость и сохраняет заказ в PostgreSQL.

**Тело запроса (JSON):**

```json
{
  "name": "Иван Иванов",
  "phone": "+79991234567",
  "email": "ivan@example.com",
  "deliveryMethod": "pickup",
  "address": "",
  "items": [
    {
      "id": 1,
      "quantity": 2
    }
  ]
}
```

**Поля запроса:**

- `name` — имя покупателя, минимум 2 символа.
- `phone` — номер телефона, от 10 до 15 цифр.
- `email` — электронная почта.
- `deliveryMethod` — `delivery` (доставка) или `pickup` (самовывоз).
- `address` — адрес, обязательный при доставке, минимум 5 символов.
- `items` — непустой массив товаров.
- `id` — идентификатор товара.
- `quantity` — количество товара от 1 до 100.

Сервер получает актуальные цены из базы данных и самостоятельно рассчитывает стоимость заказа.

При самовывозе доставка бесплатная. При доставке стоимость составляет 500 рублей, если сумма товаров меньше 8000 рублей, и 0 рублей при сумме от 8000 рублей.

**Пример успешного ответа (201 Created):**

```json
{
  "success": true,
  "message": "Заказ успешно оформлен!",
  "orderId": 1,
  "subtotal": 9980,
  "delivery": 0,
  "total": 9980
}
```

Значение `orderId` присваивается базой данных.

**Возможные ошибки:**

- `400 Bad Request` — некорректные данные покупателя, способ доставки, количество товаров или несуществующий товар.
- `500 Internal Server Error` — внутренняя ошибка сервера.

Заказ сохраняется в таблице `orders`, а его состав — в `order_items`. Для сохранения используется транзакция PostgreSQL.

### 3.6. Получение количества заказов

**Метод:** GET

**Маршрут:** `/api/orders/count`

**Описание:** возвращает общее количество записей в таблице `orders`.

**Пример ответа (200 OK):**

```json
{
  "count": 1
}
```

### 3.7. Отправка обращения в службу поддержки

**Метод:** POST

**Маршрут:** `/api/support`

**Описание:** принимает обращение пользователя и сохраняет его в таблице `support_requests`.

**Тело запроса (JSON):**

```json
{
  "name": "Иван Иванов",
  "email": "ivan@example.com",
  "subject": "Вопрос о товаре",
  "message": "Здравствуйте! Подскажите, есть ли товар в наличии?"
}
```

**Поля запроса:**

- `name` — имя пользователя, минимум 2 буквы.
- `email` — электронная почта.
- `subject` — тема обращения, от 3 до 200 символов.
- `message` — текст обращения, от 10 до 5000 символов.

**Пример успешного ответа (201 Created):**

```json
{
  "success": true,
  "message": "Ваше обращение успешно отправлено!",
  "requestId": 1
}
```

**Возможные ошибки:**

- `400 Bad Request` — некорректные данные обращения.
- `500 Internal Server Error` — внутренняя ошибка сервера.

### 3.8. Получение количества обращений

**Метод:** GET

**Маршрут:** `/api/support/count`

**Описание:** возвращает количество обращений, сохранённых в PostgreSQL.

**Пример ответа (200 OK):**

```json
{
  "count": 1
}
```

## 4. Коды HTTP-ответов

| Код | Значение |
|---|---|
| 200 OK | Запрос успешно обработан |
| 201 Created | Заказ или обращение успешно создано |
| 400 Bad Request | Переданы некорректные данные |
| 404 Not Found | Товар или API-маршрут не найден |
| 500 Internal Server Error | Внутренняя ошибка сервера |

## 5. Проверка API

Для проверки GET-запросов можно использовать браузер.

Примеры адресов:

- `http://localhost:3001/api/test`
- `http://localhost:3001/api/db-test`
- `http://localhost:3001/api/products`
- `http://localhost:3001/api/products/1`
- `http://localhost:3001/api/orders/count`
- `http://localhost:3001/api/support/count`

Для проверки POST-запросов можно использовать клиентскую часть TechMarket, Postman или curl.

При оформлении заказа данные сохраняются в таблицах `orders` и `order_items`, а при отправке обращения — в `support_requests`.

Для проверки сохранённых данных используются SQL-запросы:

```sql
SELECT * FROM orders;
SELECT * FROM order_items;
SELECT * FROM support_requests;
```

## 6. Заключение

Разработанное REST API обеспечивает взаимодействие клиентской части интернет-магазина TechMarket с сервером на Node.js и Express.

API позволяет получать информацию о товарах, оформлять заказы и отправлять обращения пользователей. Данные хранятся в PostgreSQL.

Документация содержит описание реализованных маршрутов, параметров запросов, примеры ответов и основные HTTP-коды.
